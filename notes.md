## HTML
### HTML Introducution
- Purpose: Provides the foundational content structure of web pages, separate from styling (CSS) and interactivity (JavaScript).
- Elements & Tags: HTML uses elements enclosed in tags (e.g., `<p>...</p>`) to define structure. Closing tags include a forward slash.
- Attributes: Placed inside the opening tag to describe specific details, using name/value pairs (e.g., id="unique", class="group").
- Page Structure:
    - `<html>`: The top-level container for the document.
    - `<head>`: Contains metadata and the page <title>.
    - `<body>`: Contains the entire visible content of the page.
- Hyperlinks: Created using the anchor element (`<a>`) with the href attribute defining the destination address.
- Comments: Written as \<!-- comment here --> and are completely ignored by the browser.
- Default File: Web servers automatically serve index.html when a directory is requested without a specific file name.
- Special Characters: Reserved characters must be escaped using entity syntax (e.g., using `&lt`; instead of `<`).
### Structure
- Provides structure and content to web applications using standard container elements (like `body`, `header`, `footer`, `main`, `section`, `aside`, `p`, `table`, `ol`/`ul`, `div`, and `span`).
- Proper semantic element usage ensures web pages make logical sense to developers and are correctly parsed by search engine crawlers and screen readers.
- Block elements (like `div` and `p`) create distinct layout blocks in the document flow, while inline elements (like `b` and `span`) sit inside block elements without disrupting text flow.
### Input
*More info that might be useful on the page*
- The `<form>` element acts as a container for collecting and submitting user data, using action (destination URL) and method (GET appends data to the URL; POST sends data in the request body).
- Inputs inside a form require a name attribute to serve as the key when sending key-value data pairs to the server.
- The `<input>` element uses the type attribute to define controls such as text, password, email, checkbox (inclusive choices), radio (exclusive choices), date, and color.
- Labels (`<label>`) improve accessibility and usability by linking to input fields via the for attribute matching the input's id.
- HTML5 provides built-in browser validation through input types (email, url, number), as well as attributes like required, minlength, and pattern (regular expressions).
### Media
- HTML includes media elements for external files (`img`, `audio`, `video`) and internal vector/drawing graphics (`svg`, `canvas`).
- External Media Paths: Attributes use URLs that can be full paths or relative paths (`images/photo.jpg`), where relative paths are preferred to keep code portable.
- Images & Accessibility: The `<img>` tag uses `src` to reference the image file and `alt` to provide descriptive text for accessibility and screen readers.
- Audio & Video: Use `<audio>` and `<video>` tags with `src` and optional attributes like `controls`, `autoplay`, and `loop`; external domains may require `crossorigin="anonymous"`.
- SVG (Scalable Vector Graphics): Renders vector graphics inline directly within HTML markup using XML tags like `<svg>` and `<circle>`.
- Canvas: Provides a blank standard container (`<canvas>`) meant for 2D drawing and animations created dynamically via JavaScript code (`getContext('2d')`).

## CSS
### CSS
- Rule Syntax: A rule consists of a selector and { property: value; } declarations (always end lines with ;).
- Inclusion Methods: `<link rel="stylesheet" href="...">` in `<head>` is best practice; inline styles and <style> blocks are lower priority.
- Specificity Order (Highest to Lowest): Inline Styles > ID (#id) > Class (.class) > Element (p) > Universal (*). 
- Box Model (Inside Out): Content $\rightarrow$ Padding (inner space) $\rightarrow$ Border $\rightarrow$ Margin (outer space).
- Box Sizing: box-sizing: border-box; includes padding and border in the total width/height, making layout math predictable.
    - Example Code:
    ```html
    <body>
        <p><span style="color:black">CSS</span></p>
    </body>
    ```
### Selectors
- Basic Selectors: Universal (`*`), Element (`p`), Class (`.class`), ID (`#id`), and Attribute (`[attr="val"]`).
- Combinators: Descendant (`div p`), Direct Child (`div > p`), General Sibling (`div ~ p`), and Adjacent Sibling (`div + p`).
- Child vs. Descendant: Direct child (`>`) targets only immediate children, whereas space (` `) targets nested descendants at any depth.
- Pseudo-Classes: Targets states or positions, such as mouse interaction (`:hover`) or element index (`:nth-child(n)`).
### Declarations & Styling
- Common Properties: Sizing (`width`, `height`), spacing (`padding`, `margin`), borders (`border`, `border-radius`), layout (`display`, `position`), and typography (`color`, `font-weight`).
- Typography Key: Thickness is controlled by `font-weight` (e.g., `400` normal, `700` bold), not "text-weight" or "text-thickness".
- Relative Sizing: `%` (parent relative), `em` (parent font multiplier), `rem` (root element font multiplier), `vw`/`vh` (% of viewport width/height).
- Absolute Sizing: `px` (fixed pixels).
- Color Formats: Keywords (`red`), Hex (`#00FFAA`), RGB (`rgb(r, g, b, alpha)`), and HSL (`hsl(hue, sat%, light%, alpha)`).
### Fonts
- Font Families: `serif` (flourished tips), `sans-serif` (clean lines), `fixed`/monospace (equal character width), and `symbol`.
- `font-family` Order: Accepts a fallback list of fonts; the browser uses the first available one installed or loaded.
- `@font-face`: CSS rule used to load custom font files directly from a server path.
- Third-Party Imports: Import hosted options (e.g., Google Fonts) using `@import url(...)` in CSS or `<link rel="stylesheet" href="...">` in HTML `<head>`.
### Animation
- Animation Definition: Defined using `@keyframes <name> { ... }` combined with `animation-name` and `animation-duration` properties.
- Keyframe Logic: Specifies styles at key points; `from` (0%) and `to` (100%) represent start and end, while percentage values (e.g., `50%`, `95%`) define intermediate steps.
- Property Control: Controls playback using `animation-iteration-count` (e.g., `infinite` or specific numbers) and `animation-timing-function`.
- Interpolation: Browsers automatically calculate and smoothly transition frames between keyframe states.
### Responsive Design
- Definition: Designing web applications to dynamically reconfigure layout and styling based on device screen size and orientation.
- Viewport Meta Tag: `<meta name="viewport" content="width=device-width, initial-scale=1" />` prevents mobile browsers from auto-scaling desktop layouts.
- Display Property Modes: Controls layout behavior; `block` (full width), `inline` (content width), `none` (hidden/not rendered), `flex`, and `grid`.
- Float Property: Moves elements left/right inside containers (`float: right;`), causing inline text to wrap around them automatically.
- Media Queries: Uses `@media (condition) { ... }` (e.g., `@media (orientation: portrait)` or `@media (max-width: 600px)`) to conditionally apply CSS rules based on screen traits.
### Grid
- Display Mode: `display: grid;` turns a container's direct child elements into grid items.
- Columns & Fractional Units: `grid-template-columns: repeat(auto-fill, minmax(300px, 1fr));` creates auto-filling columns where `1fr` is a dynamic fraction of available space.
- Rows & Gaps: `grid-auto-rows: 300px;` sets explicit row heights, while `grid-gap: 1em;` defines space between items.
### Flexbox
- Container Setup: `display: flex;` activates Flexbox on direct children. `flex-direction: row | column` sets the main layout axis.
- Flex Sizing (`flex: <grow> <shrink> <basis>`): `flex: 0 80px` locks an element to a fixed height/width (0 growth, 80px basis), while `flex: 1` dynamically expands to fill remaining space.
- Proportional Ratios: Sibling items with different growth values (e.g., `flex: 1` and `flex: 3`) divide available space proportionally.
- Responsive Flex & Media Queries: Combining `@media` queries with Flexbox allows dynamic layout shifts (e.g., changing `flex-direction: row` to `column` on portrait screens) or hiding components (`display: none;`).
### CSS Frameworks
- **Purpose:** Packages of pre-built CSS rulesets and JavaScript components that speed up layout development and create consistent web user experiences.
- **Tailwind vs. Bootstrap:**
  - **Tailwind:** Utility-first framework applying small, single-purpose classes directly onto HTML elements.
  - **Bootstrap:** Component-based framework providing complete, pre-styled UI elements via rich CSS class rulesets.
### Bootstrap
- **CDN Integration:**
  - Add the CSS `<link>` tag inside the `<head>` element.
  - Add the JS bundle `<script>` tag at the **end** of `<body>` for interactive components (carousel, modal, collapse, accordion).
- **Package Manager:** Can also be downloaded for local serving using Node Package Manager (`npm install bootstrap@5.3.3`).
- **Styling:** Applied by adding specific class names to HTML elements (e.g., `class="btn btn-primary"`).
### Tailwind CSS
- **Core Philosophy:** A utility-first framework providing low-level CSS class primitives (e.g., `bg-blue-400`, `p-4`, `flex`) applied directly inside HTML elements, rather than using pre-styled component classes.
- **Build Toolchain & Performance:** Scans referenced class names in your markup using a build processor (such as Vite) to dynamically build a custom, purged CSS file containing *only* used styles, preventing CSS bloat.
- **Component Workflow:** Best paired with web component frameworks (like React) to encapsulate styled markup into reusable components and eliminate repetitive inline class lists.
### Tailwind vs. Bootstrap
- **Design Philosophy:** Tailwind uses utility primitives for atomic, granular styling; Bootstrap uses pre-packaged component classes (e.g., `card`, `btn-primary`).
- **Customization & Freedom:** Tailwind allows complete control over layout, spacing, and colors without file switching; Bootstrap provides faster out-of-the-box UIs but requires CSS overrides for custom branding.
- **File Size:** Tailwind generates smaller production CSS bundles by eliminating unused rules; Bootstrap ships larger static stylesheets containing unused component styles.
- **Setup & Tooling:** Use the CDN script (`https://cdn.tailwindcss.com`) for rapid prototyping, or install `@tailwindcss/vite` with `@import 'tailwindcss';` for production builds.


## React
### JavaScript Introduction

- **Core Characteristics:** Weakly typed, interpreted scripting language running natively in browsers and Node.js. Officially named ECMAScript.
- **Execution & Errors:** Interpreted at runtime rather than pre-compiled, so syntax or variable errors are only caught when the code executes.
- **Basic Syntax:**
  - End statements with semicolons (`;`).
  - Code blocks and scope use curly braces (`{ }`).
  - Single-line (`//`) and multi-line (`/* ... */`) comments.
- **Environment & Tools:** Test code using the browser developer console (`F12` $\rightarrow$ Console) or interactive playgrounds.

### Adding JavaScript to HTML

- **Three Methods to Include JavaScript:**
  1. **External Script:** Links an external `.js` file via `<script src="index.js"></script>` (best practice for organization).
  2. **Internal Script:** Writes JavaScript directly inside `<script>` tags within the HTML document.
  3. **Inline Event Attributes:** Executes code directly inside HTML element attributes like `onclick="sayHello()"`.
- **Event Listeners:** Special attributes like `onclick` automatically create listeners for DOM events to trigger JavaScript functions or code snippets.

### Node.js

- **Overview:** JavaScript runtime built on Chrome's V8 engine that allows JS to run on servers outside the browser.
- **Basic Execution:**
  - `node -v`: Displays installed Node version (run in system terminal, not REPL).
  - `node index.js`: Runs a specific JavaScript file.
- **Node Package Manager (NPM):**
  - Bundled with Node; manages external packages and libraries.
  - `npm init -y`: Initializes a project and creates a `package.json` file.
  - `npm install <package>`: Installs dependencies into `node_modules`.
- **Dependencies & Git:** The `node_modules` folder gets very large and **must** be listed in `.gitignore`. Running `npm install` reconstructs `node_modules` from `package.json`.

### Debugging JavaScript

- **Console Debugging:** Use `console.log()` to output variable values and execution state directly to the browser console (`F12` $\rightarrow$ **Console** tab).
- **Interactive Console:** Inspect or temporarily override variables (e.g., `varCount = 50`) and execute raw JavaScript snippets live in the browser console.
- **Browser Breakpoints:** In the DevTools **Sources** tab, click on line numbers in `.js` files to add breakpoints, allowing you to pause code execution, inspect scope variables, set watches, and step through lines step-by-step.

### Debugging Node.js

- **VS Code Debugger:** Run Node.js scripts using VS Code's native debugger (`F5` $\rightarrow$ select **Node.js**).
- **Breakpoints & Controls:**
  * Click to the left of line numbers to set red-dot breakpoints.
  * Inspect variable values in the sidebar or by hovering over variables.
  * Use `F10` (step over), `F11` (step into), `F5` (continue execution), and `Shift + F5` (stop debugging).
- **Automatic Reloading (`--watch`):**
  * Execute scripts with `node --watch main.js` to automatically restart Node when files change.
  * Add `"runtimeArgs": ["--watch"]` in `.vscode/launch.json` to enable watch mode during VS Code debugging sessions.

### Web Frameworks

- **Purpose:** Frameworks simplify application development by providing tools for common tasks like modularizing code, creating Single Page Applications (SPAs), and managing reactivity.
- **Component-Based Architecture:** Modern frameworks often combine HTML, CSS, and JavaScript into hybrid file formats (like React JSX or Vue SFC), shifting focus from separate files to functional, reusable components.
- **Key Framework Tasks:** They abstract away low-level DOM manipulation, simplify state-driven UI updates, and improve overall developer productivity and code maintainability.

### Web Application Toolchains

- **Concept:** A linked pipeline of specialized tools where the output of one tool becomes the input for the next (e.g., source code to binary executable).
- **Compilation Toolchain Steps (Diagram):**
  1. **Source Code:** Raw human-readable program files.
  2. **Preprocessor:** Prepares code (resolving directives/imports) before compilation.
  3. **Compiler:** Translates high-level code into assembly/intermediate code.
  4. **Assembler:** Converts assembly into machine-level object code.
  5. **Linker:** Combines object files and external libraries into a single file.
  6. **Executable Binary:** The final runnable application.
* **Web Toolchain Utilities:** Uses specialized tools (linters, transpilers, bundlers, minifiers) to convert, package, optimize, and deploy source code into web-ready assets.

### React Notes

- **Two Core Pillars:**
  * **JSX:** Syntax for writing HTML-like UI markup directly inside JavaScript.
  * **State:** Component data that automatically triggers a page re-render whenever it changes.

- **JSX vs. `React.createElement` (Babel Transpilation):**
  * Babel converts JSX into standard `React.createElement()` calls that the browser executes to create DOM elements.
  * **`React.createElement` Syntax:** `React.createElement(tag, props, ...children)`
    * Example: `React.createElement('ol', { style: { color: 'blue' } }, React.createElement('li', null, 'BYU'))`
  * **JSX Syntax:** `<ol style={{ color: 'blue' }}><li>BYU</li></ol>`
    * **Inline Styles:** Use double curly braces `style={{ color: 'blue' }}`.
    * **JavaScript Expressions:** Embedded using single curly braces (e.g., `Item {i}` or `{3 + i}`).

- **State (`React.useState`):**
  * **Syntax:** `const [value, setValue] = React.useState(initialValue)`
  * **Tuple Structure:** Returns the current state variable (`value`) and a setter function (`setValue`).
  * **Reactivity:** Calling the setter function updates the state and forces React to automatically re-render the component.

- **DOM Mounting:**
  * Uses `createRoot(document.getElementById('root')).render(<App />)` to attach the React component tree into the HTML `<div id="root">`.

### React Components

- **Definition:** A React component is a JavaScript function that returns JSX, transpiled by Babel to build modular UI elements.
- **Component Tree:** Components can render child components, forming a nested tree starting from a single root component (`<App />`).

- **Props (Properties):**
  * Inputs passed from a parent component as element attributes (e.g., `<Demo who="world" />`).
  * Accessed inside the child component using `props.who`.

- **State & Reactivity:**
  * **State Creation:** Declared with `React.useState(initialValue)`, which returns `[value, setValue]`.
  * **Re-rendering:** Changing state via `setValue()` forces React to re-execute the component and update the UI.
  * **Virtual DOM & Diffing:** React compares updated JSX against the previous version ("diffing") and updates only the changed elements in the actual browser DOM.

- **Styling Components:**
  * **CSS Classes:** Use `className` instead of `class` because `class` is a reserved JavaScript keyword.
  * **Dynamic Inline Styles:** Pass a JavaScript object using double curly braces (e.g., `style={{ color: color }}`).

### React Router Notes

- **Single-Page Application (SPA) Concept:**
  * Loads one HTML page and uses JavaScript to manipulate the DOM to display different views.
  * Retains app state and prevents full page reloads when navigating.

- **Package:** `react-router-dom` provides client-side routing.

- **Core Components:**
  * **`<BrowserRouter>`:** Encapsulates the app and connects routing to the browser's location history.
  * **`<NavLink>` / `<Link>`:** Navigation element that updates the URL without reloading the page (uses `to="/path"`).
  * **`<Routes>`:** Container that holds route definitions and displays the matching route component.
  * **`<Route>`:** Maps a URL path to a React component using props: `<Route path="/green" element={<Page />} />`.

## React Pt2

### JavaScript Console

* **Definition**: Runtime debugger console in the browser (distinct from the OS terminal/command line).
* **`console.log()`**: Outputs values and objects with support for string placeholders (`'%s'`) and CSS styling (`'%c'`).
* **`console.time()` & `console.timeEnd()`**: Measures code execution duration in milliseconds using matching labels.
* **`console.count(label)`**: Tracks and logs how many times a specific code block or label executes.
* **Best Practices**: Quick for small fixes, but IDE debuggers are superior; **must be removed before production deployment.**

### JavaScript Functions

* **First-Class Objects**: Functions can be assigned to variables, passed as parameters, returned from other functions, and stored in arrays or objects.
* **Syntax & Typing**: Declared using the `function` keyword; parameter and return types are **inferred** (no explicit type declarations).
* **Default Parameters**: Unsupplied parameters evaluate to `undefined` unless a default value is specified in the function signature (e.g., `title = 'default'`).
* **Anonymous Functions**: Functions defined without an identifier, commonly assigned to variables or passed inline as arguments (e.g., `const add = function(a, b) { return a + b; }`).
* **Inner Functions**: Functions declared inside other functions to encapsulate helper logic and restrict scope.

### Arrow Functions

* **Syntax & Returns**: 
  * Defined with `=>` (fat arrow); always anonymous.
  * **Implicit Return**: Omit curly braces `{}` and `return` for single expressions (e.g., `() => 3`).
  * **Explicit Return**: Using curly braces requires an explicit `return`, otherwise it evaluates to `undefined`.
* **Lexical `this` (MCQ Focus)**: 
  * Inherits `this` from the **surrounding scope where it was defined** (lexical scoping), unlike regular functions whose `this` is determined dynamically at call-time.
* **Limitations (When NOT to use)**:
  * **Object Methods**: `this` will point to the global/undefined object instead of the object instance.
  * **Constructors**: Cannot be used with the `new` keyword and lack a prototype property.
  * **Arguments**: Do not have their own `arguments` object (use rest parameters `...args` instead).
* **Closures & React Usage**: 
  * Captures the environment/variables at creation time (ideal for factory patterns).
  * In React, combine with functional state updates (e.g., `setCount(prev => prev + 1)`) to handle asynchronous state safely.

### JavaScript Arrays

* **Definition**: Dynamic, zero-indexed, mixed-type list objects.
* **Performance**: `.push()`/`.pop()` are fast (O(1)); `.unshift()`/`.shift()` are slow (O(n) due to re-indexing).
* **Key Methods**: 
  * *Transform*: `.map()`, `.filter()`, `.reduce()`, `.sort()` (in-place).
  * *Test/Search*: `.every()`, `.some()`, `.find()`.
* **Gotchas**: Copied by **reference**; sparse arrays create empty holes.

### JavaScript Objects and Classes

* **Objects & Literals**: Collections of name-value pairs created via `new Object()` or object-literal syntax (`{ a: 3 }`). Accessed via dot (`obj.prop`) or bracket (`obj['prop']`) notation.
* **Static Methods**: `Object.entries()` (key-value pairs), `Object.keys()` (keys), and `Object.values()` (values).
* **Constructors & `this`**: Functions returning an object and called with `new`. The `this` keyword points to the current object instance.
* **Classes & Private Fields**: Blueprints with an explicit `constructor()`. Prefix fields/methods with `#` to make them private.
* **Inheritance**: Subclasses use `extends` and `super()` to inherit from parent classes; child methods override parent methods.
* **Dynamic Manipulation**: Properties and methods can be added, modified, or deleted at runtime on individual instances without altering the class blueprint.

### JavaScript Destructuring

* **Definition**: Process of extracting values from arrays or properties from objects into distinct variables.
* **Array Destructuring**: Position-based assignment (`const [b, c] = arr;`) with support for rest syntax (`const [b, ...others] = arr;`).
* **Object Destructuring**: Explicit property matching (`const { prop } = obj;`), variable renaming (`const { prop: alias } = obj;`), and default values (`const { prop = defaultVal } = obj;`).
* **React Usage**: Heavily used for component parameters (e.g., `function Component({ prop })`) and hook returns (`const [state, setState] = useState()`).

### JavaScript Time and Intervals

* **`setTimeout()`**: Executes a callback function *once* after a specified delay in milliseconds. Does not block subsequent code execution.
* **`setInterval()`**: Periodically executes a callback function repeatedly at a given millisecond interval.
* **`clearInterval()`**: Cancels an active interval timer by passing the reference returned by `setInterval()`.
* **Asynchronous Flow**: Code execution continues past timer functions; callbacks are queued and run by the runtime after the delay or interval expires.

### React Hooks

* **Rules of Hooks**: Must be called at the top scope of the component (never inside loops or conditionals) to ensure consistent execution order.
* **`useState`**: Manages local state within functional components.
* **`useEffect`**: Handles lifecycle events and side effects. 
  * *Dependencies*: Omit for every render; pass `[]` to run only on initial mount; pass `[var]` to run when specific variables change.
  * *Cleanup*: Return a cleanup function inside `useEffect` to tear down resources (e.g., closing database connections) when components unmount.
* **`useContext`**: Eliminates **prop drilling** by providing global data access (such as themes or authentication) directly to deeply nested components without passing props through intermediate middlemen.
* **`useMemo`**: Caches (memoizes) expensive calculation results between renders based on a dependency array. Providing an empty array `[]` runs the calculation **only once during initial mount** and returns the cached result for all subsequent renders.

### React reactivity

* **Core Pillars**: UI reactivity is driven by three foundational concepts: `props`, `state`, and `render`.
* **State Management & Rerendering**: React maintains an internal table of state values. When an update method is called, React flags the change and periodically rerenders any component dependent on that state.
* **Component Architecture**: 
  * *Parent Components*: Manage and hold the state.
  * *Child Components*: Receive state values via `props` and receive update functions to modify the parent's state.
* **Asynchronous Updates**: State updates happen **asynchronously**—calling an update function does not immediately update the variable value on the very next line of code.
* **Controlled Components**: Binding form elements (`value={state}` with an `onChange` handler) ensures seamless two-way synchronization between user input and component state.

### JSON (JavaScript Object Notation)

* **Data Types**: Supports strings, numbers, booleans, arrays, objects, and `null` (always encoded in UTF-8).
* **Syntax Rules**: Mandatory double quotes `"` for both keys and string values; trailing commas and comments are strictly forbidden.
* **JavaScript Conversion**: 
  * `JSON.stringify()`: Converts a JS object into a JSON string (note: properties with `undefined` or function values are omitted entirely).
  * `JSON.parse()`: Converts a JSON string back into a JS object.
* **Dates**: Handled using standard [ISO 8601](https://datatracker.ietf.org/doc/html/rfc8259) formatted strings since JSON has no native date type.
* **Best Practices**: Keep structures flat, use consistent naming conventions, and return top-level objects rather than raw arrays in API responses.

### JavaScript LocalStorage

* **Core API**: Methods include `setItem()`, `getItem()`, `removeItem()`, and `clear()`.
* **Data Serialization**: Only stores strings. Complex structures (objects/arrays) require `JSON.stringify()` on save and `JSON.parse()` on retrieval.
* **Limits & Errors**: ~5MB capacity per origin; throws a `QuotaExceededError` when full (use `try...catch` blocks).
* **Security (XSS)**: Vulnerable to Cross-Site Scripting. **Never** store sensitive data (passwords, PII, auth tokens) here.
* **Performance**: Synchronous operations block the main thread, which can cause UI lag if overused.
* **LocalStorage vs. SessionStorage**: LocalStorage persists across browser sessions and restarts; `sessionStorage` clears when the specific tab or session closes.

### JavaScript Promises

* **Core Concept**: Represents the eventual completion or failure of an asynchronous operation, preventing long-running tasks from blocking the single-threaded UI rendering process.
* **Creation**: Instantiated using the `new Promise()` constructor with an executor function that accepts `resolve` and `reject` callback parameters.
* **States**: Always exists in one of three states: `pending` (currently running), `fulfilled` (completed successfully via `resolve()`), or `rejected` (failed via `reject()`).
* **Handlers**: Results are processed using `.then()` for successful fulfillment, `.catch()` for errors and rejections, and `.finally()` for cleanup code that always executes.
* **Chaining**: Allows sequential asynchronous operations to be linked together cleanly by chaining multiple `.then()` calls one after another.

### JavaScript Async/await

* **Core Concept**: A cleaner syntax wrapper (syntactic sugar) over Promises that allows asynchronous code to be written and read like standard synchronous code.
* **`async` Keyword**: Placed before a function declaration to designate it as asynchronous, ensuring the function automatically returns a Promise resolving to its return value.
* **`await` Keyword**: Pauses execution inside an `async` function until a Promise settles (resolves or rejects), directly unwrapping and returning the resulting value.
* **Error Handling**: Replaces `.catch()` chaining with familiar synchronous `try...catch...finally` blocks to handle rejected promises and exceptions gracefully.
* **Readability**: Eliminates deeply nested callback and `.then()` chains, keeping sequential asynchronous workflows (such as network fetches and JSON parsing) clean and straightforward.

### JavaScript String

* **Syntax & Creation**: Primitive type defined using single quotes (`'`), double quotes (`"`), or backticks (`` ` ``).
* **Immutability**: Strings cannot be modified in place. Any operation or direct index assignment (e.g., `str[0] = 'a'`) leaves the original string untouched and returns a new one.
* **Template Literals**: Backticks (`` ` ``) enable multi-line strings and dynamic string interpolation using `${expression}` syntax.
* **Common Methods**: Includes built-in utilities like `indexOf()`, `split()`, `slice()`, `trim()`, `replace()`, `toLowerCase()`, and `toUpperCase()`.
* **Character Access**: Characters are retrieved using bracket notation (`str[index]`) or the `.charAt(index)` method.
* **Comparison & Length**: Compared lexicographically using case-sensitive Unicode values; the `.length` property returns the count of UTF-16 code units.

### JavaScript Types, Operators, Conditionals, and Loops

* **Variables**: Declared using `let` (mutable) or `const` (immutable); `var` is deprecated due to scope issues.
* **Primitives & Objects**: Includes primitive types (Null, Undefined, Boolean, Number, BigInt, String, Symbol) and common objects (Object, Array, Date, Map, JSON).
* **Type Coercion & Equality**: Loose equality (`==`) performs automatic type conversion, whereas strict equality (`===`) checks both value and type, making it the preferred standard.
* **Conditionals**: Handled via standard `if`/`else` structures, ternary operators, and short-circuiting boolean logical operators (`&&`, `||`, `!`).
* **Loops**: Supports `for`, `while`, `do...while`, `for...in` (iterates over object keys/indexes), and `for...of` (iterates over values), with `break` and `continue` control flow.

### Document Object Model (DOM)

* **Core Concept**: An object-based hierarchical tree representation of HTML elements that the browser uses for rendering and exposes to JavaScript for dynamic manipulation via the global `document` variable.
* **Node Structure**: Everything in a document—including elements, attributes, text, and comments—forms a node within the DOM tree, with the document node at the root.
* **Accessing Elements**: Elements are queried using CSS selectors via `document.querySelector()` and `document.querySelectorAll()`, with text and HTML accessed through `.textContent` and `.innerHTML`.
* **Modifying the DOM**: Elements can be dynamically created with `document.createElement()`, inserted using `.appendChild()`, and removed via `.removeChild()`.
* **Security Risk**: Directly setting untrusted user data into `.innerHTML` opens the application to Cross-Site Scripting (XSS) injection attacks; inputs should be sanitized or safe DOM methods used instead.
* **Event Listeners**: Functions attached via `.addEventListener()` (or inline handlers) that respond to user interactions such as mouse clicks, keyboard strokes, focus shifts, and form submissions.

### JavaScript Regular Expressions

* **Core Concept**: Built-in textual pattern matchers used to search, validate, or replace text within strings, created either via regex literals (`/pattern/flags`) or the `RegExp` class constructor.
* **Key Methods**: Includes `RegExp` methods like `.test()` (returns boolean) and `.exec()` (returns match array), alongside `String` methods such as `.match()`, `.replace()`, `.search()`, and `.split()`.
* **Advanced Flags**: Modifiers like `g` (global), `i` (case-insensitive), `m` (multiline), `s` (dotAll), `u` (Unicode), and `y` (sticky) that alter matching behavior.
* **Assertions (Lookarounds)**: Zero-width matching checks based on surrounding context without consuming characters, including positive/negative lookaheads (`(?=...)`, `(?!...)`) and lookbehinds (`(?<=...)`, `(?<!...)`).
* **Groups & Backreferences**: Parentheses create capturing groups `(...)`, named groups `(?<name>...)`, non-capturing groups `(?:...)`, and backreferences (`\n`) to reference prior matches.
* **State & `lastIndex`**: Maintains matching state when using `g` or `y` flags via the `lastIndex` property, which tracks the index position for subsequent searches.
* **Character Shortcuts**: Shorthand character classes like `\d` (digits), `\w` (word characters), and `\s` (whitespace), alongside Unicode property escapes (`\p{...}`).

### JavaScript Rest and Spread

* **Rest Parameter (`...`)**: Combines an unknown number of function arguments into a single array, and must always be placed as the final parameter in a function definition.
* **Spread Operator (`...`)**: Expands iterables (arrays, strings, sets, or iterators like `matchAll()`) into individual elements or function arguments.
* **Shallow Copying**: Spread creates a top-level clone of arrays or objects, meaning nested structures are still shared by reference.
* **Object Merging & Overwriting**: Combines objects using spread where duplicate keys are overwritten by the property from the *last* object spread.
* **String Conversion**: Converts strings into an array of individual characters (`[...string]`).
* **Immutability in State**: Widely used in frameworks like React to copy and update state objects without mutating the original reference.

### JavaScript Exceptions

* **Core Syntax**: Handled using `try` (normal execution), `catch (err)` (handles thrown or runtime errors), and `finally` (always executes regardless of outcome).
* **Throwing Errors**: Triggered via the `throw` keyword; best practice is to always throw instances of the `Error` object (or subclasses) to preserve stack traces rather than raw strings or numbers.
* **Flow Control Caution**: Exceptions should be reserved for truly exceptional conditions, not normal control flows (like missing optional files or user input validation).
* **Fallback Pattern**: Wrapping risky actions (like network requests) in a `try` block with a fallback implementation (such as reading from `localStorage`) in the `catch` block.
* **Custom Error Classes**: Extend the base `Error` class to create domain-specific errors with custom metadata and identifiers.
* **Error Chaining**: Wrap low-level errors inside new high-level ones using the `{ cause: lowLevelErr }` property to maintain context and stack traces.
* **Asynchronous Handling**: Promises require `.catch()` chains to handle rejections, while `async/await` code must be wrapped in `try...catch` blocks.
* **Global Error Catching**: Catch missed errors using window/process listeners like `unhandledrejection` and `uncaughtException`.

### JavaScript Scope

* **Core Definition**: The set of variables visible in the current execution context, divided into Global, Module, Function, and Block scopes.
* **`var` vs `let`/`const`**: `var` ignores block scope and hoists to function scope; best practice is to avoid it entirely in favor of `let` and `const`.
* **`this` Keyword**: References the object containing the current execution context (evaluates to `globalThis`, the owning object, or `undefined` in strict mode).
* **Closures**: Functions that remember and retain access to their surrounding creation state, with arrow functions lexically inheriting `this` from their creation context.

## HTTP Service

### Web Servers

* **Core Definition**: Computing hardware and software hosting web services that accept incoming internet connections and speak the HTTP protocol.
* **Monolithic vs. Modern Servers**: Early servers required separate software packages (Apache, Nginx); modern web applications embed the HTTP service directly using libraries like Express.
* **Web Service Endpoints**: Custom programmatic routes added to applications to return dynamic data or execute backend logic beyond serving static HTML.
* **Web Service Gateways (Reverse Proxy)**: Centralized services listening on port 443 that handle SSL termination, load balancing, and route public requests to internal ports.
* **Microservices & Serverless**: Microservices partition system functionality into independent, horizontally scalable services, while serverless abstracts infrastructure entirely down to individual gateway-managed endpoints.

### Web Services Introduction

* **Frontend vs. Backend**: Frontend runs in the browser (HTML/CSS/JS/images) via HTTPS; backend runs on the server to handle static files, endpoints, business logic, and data persistence.
* **Web Service Endpoints (APIs)**: Custom programmatic routes exposed by the backend to handle requests (like creating users or fetching scores) and return data.
* **The `fetch` Function**: A built-in browser function used by frontend JavaScript to make asynchronous HTTP requests to endpoints.
* **Request-and-Update Cycle**: The core mechanism where the frontend fetches data (such as JSON) and dynamically updates the DOM without reloading the full page.

### URL (Uniform Resource Locator)

* **Core Definition**: A string representing the location and access protocol of any web resource (web pages, images, JSON objects, etc.).
* **Required Components**: The **scheme** (protocol like `https`) and the **domain name** are mandatory; all other parts are optional.
* **Structure Syntax**: `<scheme>://<domain name>:<port>/<path>?<parameters>#<anchor>`
* **Path & Parameters**: The **path** specifies the resource route, while **parameters** (query string) pass key-value qualifiers separated by `&`.
* **Anchor / Fragment ID**: A hash component (`#`) used to reference a sub-location or target a specific element ID for client-side scrolling.
* **URL vs URI/URN**: A URN is a unique name without location, a URI is a general identifier encompassing both, but web programming uses URLs.

### Ports

* **Core Definition**: Numeric identifiers paired with IP addresses that allow a single device to route incoming traffic across multiple network protocols and internal services.
* **Port Ranges (IANA)**: Divided into **Well-Known** (0–1,023 for core system protocols like HTTP 80 and HTTPS 443), **Registered** (1,024–49,151 for user apps), and **Dynamic/Private** (49,152–65,535).
* **Server Architecture & Caddy**: External requests hit standard ports (80/443) where Caddy proxies and routes traffic inward to unique internal service ports (e.g., port 3000 for Simon, port 4000 for Startup).
* **Ephemeral Ports**: Temporary, high-numbered dynamic ports assigned by the client OS for outbound requests, allowing servers to return responses to the correct browser socket.

### HTTP (Hypertext Transfer Protocol)

* **Core Protocol**: The foundational protocol for client-server communication using stateless request and response cycles.
* **Request Syntax**: Consists of a method line (`<verb> <url path> <version>`), optional key-value headers, and an optional body separated by two newlines.
* **Response Syntax**: Consists of a status line (`<version> <status code> <status string>`), optional headers, and an optional body.
* **Common Verbs**: `GET` (retrieve resource), `POST` (create resource), `PUT` (update resource), `DELETE` (remove resource), and `OPTIONS` (metadata lookup).
* **Status Code Ranges**: Divided into `1xx` (Informational), `2xx` (Success, e.g., `200` OK, `201` Created), `3xx` (Redirects/Caching, e.g., `304` Not Modified), `4xx` (Client Errors, e.g., `401` Unauthenticated vs. `403` Forbidden), and `5xx` (Server Errors, e.g., `500`).
* **Headers & Body**: Metadata key-value pairs (e.g., `Authorization`, `Content-Type`, `Cookie`) managing security, caching, and data formats; body format is dictated by the `Content-Type` MIME type.
* **Cookies**: Server-generated key-value pairs (`Set-Cookie`) stored on the client and returned on subsequent requests (`Cookie`) to track user state and bypass HTTP statelessness.
* **Protocol Evolution**: Progressed from HTTP/0.9 (basic text get) and HTTP/1.1 (persistent connections, CRUD methods) to HTTP/2 (multiplexing) and HTTP/3 (QUIC protocol, default encryption).

### Fetch API

* **Core Definition**: The modern browser-native API used by client-side JavaScript to make asynchronous HTTP requests, replacing legacy `XMLHttpRequest`.
* **Promise-Based Flow**: `fetch()` accepts a URL and returns a promise that asynchronously resolves to an HTTP response object.
* **Response Handling**: The `.json()` method on the response object parses JSON payloads into usable JavaScript objects.
* **HTTP Methods**: Defaults to `GET` requests; `POST` requests require an options configuration specifying `method`, `headers` (e.g., `'Content-type': 'application/json'`), and a `JSON.stringify()` request body.
* **Error Handling**: Implementing `.catch()` blocks ensures network errors and failed requests are captured gracefully.

### Using Public APIs

* **Core Definition**: Third-party services exposing endpoints (URLs) that return data (usually JSON) to transform static pages into dynamic, data-driven applications.
* **API Evaluation**: When selecting public APIs, verify authentication requirements, HTTPS support, and CORS (Cross-Origin Resource Sharing) compatibility.
* **Fetch Workflow**: Uses the asynchronous `fetch()` function which returns a Promise, parsed via `.json()` to update the UI dynamically.
* **API Keys & Auth**: Unique identifiers used to enforce rate limits and prevent abuse, typically passed via query parameters or request headers.
* **Common Challenges**: Mitigating rate limits (HTTP 429), handling unpredictable data schema changes, and managing network latency with loading states.

### Service Design

* **Core Purpose**: Web services provide backend functionality such as user authentication, session tracking, and data storage.
* **Model & Sequence Diagrams**: Design applications around domain-specific user objects (avoiding infrastructure details) and use sequence diagrams to map out object interactions and endpoints.
* **Leveraging HTTP**: Maximize native HTTP infrastructure (standard verbs, MIME types, caching servers, and proxies) rather than custom-building networking layers.
* **Endpoint Design Principles**: Endpoints should be **Grammatical** (resources as nouns), **Readable** (clear URL paths), **Discoverable** (linking related resources), **Compatible** (backward-compatible JSON updates), **Simple** (single-purpose), and **Documented** (using OpenAPI/Swagger).
* **RPC (Remote Procedure Call)**: Action-oriented paradigm that treats services like remote function calls, typically leveraging POST requests with action names.
* **REST (Representational State Transfer)**: Resource-oriented paradigm using standard HTTP verbs (GET, POST, PUT, DELETE) and unique URL paths to optimize caching and state handling.
* **GraphQL**: Client-driven flexibility paradigm utilizing a single unified query endpoint that allows clients to define the exact shape of data returned to prevent over-fetching.

### Node Web Service

* **Core Definition**: Using Node.js backend code to listen on a network port, process incoming HTTP requests, and send responses.
* **Prerequisites & Setup**: Install the LTS version of Node.js, check versions (`node -v` and `npm -v`), initialize a project using `npm init -y`, and create an `index.js` file.
* **HTTP Module (`http`)**: Built-in Node.js module used to create a server via `http.createServer()`, handling incoming request (`req`) and response (`res`) objects.
* **Server Listening**: `server.listen(port, callback)` starts the server, allowing it to accept connections on a specific local port (e.g., `localhost:3000`).
* **Debugging & Execution**: Run code via `node index.js` in the terminal or press `F5` in VS Code to attach the built-in Node.js debugger.
* **Workflow Shift**: Replaces the VS Code Live Server extension with Node.js to run backend services and serve application code.

### Express Framework

* **Core Definition**: A production-ready Node.js web framework that simplifies request routing, JSON parsing, middleware execution, and HTTP response handling.
* **App Initialization**: Instantiated by requiring express (`const app = express()`) and binding to a network port (`app.listen(port)`).
* **Defining Routes**: Maps HTTP verbs (`get`, `post`, `put`, `delete`) to URL paths (e.g., `app.get('/store/:name', ...)`), using `req.params` to capture dynamic path variables.
* **Middleware Pattern**: Functions matching `(req, res, next)` that execute sequentially. Must invoke `next()` to pass control down the chain unless a response is fully terminated.
* **Built-in & Third-Party Middleware**: 
  * Built-in: `express.static('public')` for serving static web assets.
  * Third-party: External packages like `cookie-parser` injected via `app.use()` to manage cookies (`req.cookies` and `res.cookie()`).
* **Error-Handling Middleware**: Specialized functions featuring a four-parameter signature `(err, req, res, next)` that catch application errors and return structured failure responses (e.g., status 500).
* **Debugging**: Executed and inspected in VS Code using the Node.js debugger (`F5`), with the ability to step directly into third-party package source code inside `node_modules` (`F11`).

### JavaScript Modules

* **CommonJS**: Node.js standard using `require()` to import and `module.exports` to export.
* **ES Modules**: Modern standard using `import` and `export` keywords (requires `"type": "module"` in `package.json`).
* **File Overrides**: Use `.cjs` and `.mjs` extensions to explicitly override global module configuration.
* **Browser Scoping**: Browser ES modules are isolated; functions/variables must be attached to the global `window` object to be accessed by inline HTML event handlers.

### PM2 (Process Manager 2)

* **Core Definition**: A process manager and daemon that keeps Node.js backend applications running continuously in the background across console closures and server reboots.
* **Process Monitoring (`pm2 ls`)**: Displays a dashboard of hosted node processes, tracking unique IDs, names, execution modes, restart counters, status (`online`), and real-time CPU/memory usage.
* **Essential Lifecycle Commands**:
  * `pm2 start index.js -n <name> -- <port>`: Registers and starts a new named process on a specific port.
  * `pm2 stop <name>` / `pm2 restart <name>` / `pm2 delete <name>`: Controls, reloads, or removes active hosted processes.
  * `pm2 save`: Persists the current process configuration table across system reboots.
  * `pm2 logs <name>`: Displays live process logs for debugging runtime errors.
* **Deployment Workflow**: Used in conjunction with Caddy reverse proxy configuration to host and manage separate production web services on an AWS server.
